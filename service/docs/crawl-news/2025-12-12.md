## Denial of Service and Source Code Exposure in React Server Components

**ソース:** React Blog

## React Server Components における新たな脆弱性（DoS、ソースコード漏洩）について

React Server Components において、先週の修正された脆弱性を悪用しようとする過程で、新たに2つの脆弱性が発見・開示されました。

1.  **DoS (Denial of Service) 脆弱性 (CVE-2025-55184)**：これは、サーバーへの過剰な負荷をかけ、サービス停止を引き起こす可能性のある「高」レベルの脆弱性です。
2.  **ソースコード漏洩脆弱性 (CVE-2025-55183)**：これは、サーバー上のソースコードの一部が外部に漏洩する可能性のある「中」レベルの脆弱性です。

これらの脆弱性は、React Server Components を利用する開発者にとって、セキュリティリスクの増大を意味します。最新のセキュリティ情報を注視し、必要に応じてアップデートや対策を講じることが重要です。

🔗 [記事を読む](https://react.dev/blog/2025/12/11/denial-of-service-and-source-code-exposure-in-react-server-components)

## React Server Components security update: DoS and Source Code Exposure

**ソース:** Vercel Blog

React Server Components (RSC) に、高深刻度のサービス拒否 (DoS) 脆弱性 (CVE-2025-55184) と中深刻度のソースコード漏洩 (CVE-2025-55183) の 2 件が新たに見つかりました。これらは、以前の脆弱性の修正パッチを調査する過程で発見されました。これらの脆弱性は、悪意のある HTTP リクエストにより、サーバープロセスがハングアップしたり、Server Actions のコンパイル済みソースコードが漏洩する可能性があります。ただし、リモートコード実行はできません。Vercel は WAF で自動保護を行っていますが、速やかなライブラリのアップデートが必須です。影響を受けるのは React 19.0.0 から 19.2.1 までのバージョンと、それらを利用する Next.js 13.x～16.x などのフレームワークです。

**修正:**
* React: 19.0.2, 19.1.3, 19.2.2
* Next.js: 14.2.34, 15.0.6, 15.1.10, 15.2.7, 15.3.7, 15.4.9, 15.5.8, 15.6.0-canary.59, 16.0.9, 16.1.0-canary.18

開発者は速やかに最新バージョンにアップデートすることを強く推奨します。

🔗 [記事を読む](https://vercel.com/changelog/react-server-components-security-update-dos-and-source-code-exposure)

## 5 Lessons for enabling self-service and AI-driven infrastructure despite legacy tech at a national bank

**ソース:** HashiCorp Blog

大手銀行がレガシー技術を抱えつつ、セルフサービスとAI駆動のインフラを実現するための5つの教訓は以下の通りです。

1.  **レガシーを無視せず未来を構築する:** 抽象化により、新旧技術間の橋渡しを行う。
2.  **標準化はセキュリティとスケールの基盤:** 一元化されたプラットフォームと不変テンプレートでリスクを低減し、セキュリティチームの信頼を得る。
3.  **セキュリティとセルフサービスをプラットフォームに組み込む:** 開発者はインフラ管理ではなくコーディングに集中できる。
4.  **開発者生産性をビジネス指標として測定:** 開発時間を可視化し、自動化やツールの投資対効果を証明する。
5.  **AIはエンジニアを増幅させるもので、置き換えるものではない:** AIはコード品質向上やテスト自動化を加速し、創造的なタスクへの集中を促す。

この教訓は、技術的負債を抱える企業でも、現代的なエンジニアリングプラットフォームを通じて変革を遂げられることを示唆しています。
