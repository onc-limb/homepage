## Limit on-demand concurrent builds to one build per branch

**ソース:** Vercel Blog

## On-Demand Concurrent Buildsの同時実行上限をブランチごとに1つに制限

Vercelの「On-Demand Concurrent Builds」機能において、ブランチごとの同時実行上限が1つに設定できるようになりました。この機能により、ビルドキューをスキップして即時実行が可能でしたが、今後は同一ブランチへのデプロイはキューイングされ、アクティブなビルド完了後に最新のキューイングされたデプロイのみがビルドされます。古いキューイングされたデプロイはスキップされます。異なるブランチ間のビルドは引き続き並行して実行可能です。この設定はプロジェクト設定から有効化できます。

🔗 [記事を読む](https://vercel.com/changelog/limit-on-demand-concurrent-builds-to-one-build-per-branch)

## What happened to WebAssembly

**ソース:** Hacker News Best

## WebAssembly の現状と将来性

WebAssembly (Wasm) は、ブラウザでネイティブに近いパフォーマンスでコードを実行できる技術として登場しましたが、その普及は期待ほど進んでいません。記事では、Wasm が当初想定していたような「JavaScript の代替」という位置づけではなく、むしろ「ブラウザ外での利用」や「既存コードの移植」といった、よりニッチな領域で価値を発揮していると分析しています。

### 技術的なポイント

*   **ブラウザ内での利用:**
    *   JavaScript へのコンパイル、または JavaScript との連携が中心。
    *   パフォーマンス向上に貢献するものの、JavaScript 自体の進化も速く、Wasm への移行メリットが限定的。
    *   JavaScript のリプレイスというよりは、パフォーマンスが求められる特定処理の高速化に利用される傾向。
*   **ブラウザ外での利用 (WASI):**
    *   サーバーサイド、エッジコンピューティング、IoT など、ブラウザ外での利用が拡大。
    *   プラットフォーム非依存の実行環境として期待。
    *   モジュール化やセキュリティ、エコシステムの成熟が課題。
*   **将来性:**
    *   「JavaScript の代替」から「汎用的な実行環境」へと進化。
    *   ブラウザ内では補助的な役割、ブラウザ外では主要な役割を担う可能性。
    *   開発者にとっては、既存コードの移植や、パフォーマンスが求められる特定用途での活用が現実的な選択肢。

### 開発者にとって重要な情報

*   **Wasm を「JavaScript の代替」として捉えるのは現時点では誤解。**
*   **パフォーマンスが重要な処理（ゲーム、動画編集、CAD など）のブラウザ内での高速化に活用できる。**
*   **ブラウザ外（サーバーサイド、エッジ、IoT など）での利用に大きな可能性を秘めている。**
*   **WASI の進化により、ブラウザ外での Wasm の利用がさらに容易になる。**
*   **既存の C/C++ などのコードを Web に移植する手段としても有効。**

### まとめ

WebAssembly は、当初の期待とは異なる形で進化を遂げていますが、その汎用性とパフォーマンスは依然として魅力的です。開発者は、Wasm を JavaScript の代替ではなく、特定の課題解決のための強力なツールとして理解し、活用していくことが重要です。特に、ブラウザ外での利用は今後ますます注目されるでしょう。

🔗 [記事を読む](https://emnudge.dev/blog/what-happened-to-webassembly/)

## Anthropic blocks third-party use of Claude Code subscriptions

Anthropicは、同社のAIモデル「Claude」のコーディング機能に特化したサブスクリプションサービス「Claude Code」について、サードパーティプラットフォームからの利用をブロックしました。これは、AnthropicがClaude Codeの利用規約を更新したことによるもので、API経由での利用は引き続き可能ですが、OpenAIのChatGPT Plusのような一般ユーザー向けのサブスクリプションモデルを直接参照する形での利用が制限されます。

**技術的ポイント:**

*   **API経由での利用は継続:** Anthropicは、開発者向けAPIを通じてClaude Codeの機能を提供し続ける方針です。
*   **一般ユーザー向けサブスクリプションへの影響:** ChatGPT Plusのように、一般ユーザーが直接サブスクリプションとして利用できる形式のサービスが、Claude Codeでは制限されることになります。

**開発者にとっての重要情報:**

この変更は、Claude Codeの機能を自社サービスに組み込もうと考えていた開発者にとって、直接的な影響はありません。APIを利用した統合は引き続き可能です。しかし、Anthropicが直接提供する一般ユーザー向けのサブスクリプションモデルとは異なる形態でClaude Codeが提供されることになるため、将来的なサービス展開や連携方法に影響を与える可能性があります。

## I got tired of memorizing swaggo comment order, so I made this

真のAI駆動開発は、「契約」によってAIの振る舞いを制約します。この「契約」とは、受け入れテスト、単体テスト、スキーマ、型などのことです。

このアプローチにより、AIはテストという「契約」に縛られ、開発者はコードの正確性、セキュリティ、運用に対する責任を維持できます。AIはあくまでツールであり、最終的な品質保証は人間とテストが行うのです。
