## I found a useful Git one liner buried in leaked CIA developer docs

**ソース:** Hacker News Best

CIAの流出した開発者ドキュメントに、マージ済みのGitブランチを効率的に削除する便利なワンライナーが見つかりました。このコマンドは、`git branch --merged`でマージ済みのローカルブランチをリストアップし、`grep -v main`（または`master`）でメインブランチを除外し、`xargs git branch -d`でそれらを一括削除します。これにより、開発者は不要なブランチを手動で探して削除する手間を省き、リポジトリをクリーンに保つことができます。これは、Gitの管理を効率化したい開発者にとって非常に役立つテクニックです。

## Open Source Maintenance: Do I Need to Update My License Year?

**ソース:** Dev.to

オープンソースプロジェクトのライセンス年表記について、プロジェクトが長期間にわたる場合、「2019」のような開始年のみの表記はプロジェクトが放置されている印象を与える可能性があります。MITやApacheライセンスでは、年表記は初版公開年を示しますが、よりプロフェッショナルな標準は「開始年-現在年」の範囲表記です。例えば、「Copyright (c) 2019-2026」とすることで、過去のバージョンと最新版の両方が保護され、プロジェクトがアクティブにメンテナンスされていることを示せます。セマンティックバージョニングに従う場合、パッチバージョンごとにライセンスを更新する必要はありませんが、メジャーバージョンやマイナーバージョンへの更新時には、最新の年を反映させることが推奨されます。手動更新が煩雑な場合は、GitHub Actions (`FantasticFiasco/action-update-license-year`) を利用して、毎年1月1日に自動更新させることも可能です。

## Chromeにおける証明書有効期限制限の仕組みとプライベートCAの扱い

**ソース:** Qiita

Chromeにおける証明書有効期限制限は、セキュリティ強化のためCA/Browser Forumによって推進されています。現在398日の最長有効期限は段階的に短縮され、2029年3月15日以降は47日になります。この変更は、証明書の鮮度を保ち、不正利用リスクを低減することを目的としています。

**開発者にとっての重要ポイント:**

*   **短期間での証明書更新が必須:** 47日という短い有効期限に対応するため、TLS証明書の自動更新メカニズムの構築や、証明書管理ライフサイクルの見直しが急務となります。
*   **プライベートCAの扱い:** パブリックCAとは異なり、プライベートCA発行の証明書は有効期限の短縮対象外ですが、Chromeの信頼ストアに登録されていない場合、信頼されず警告が表示される可能性があります。内部システム等でプライベートCAを利用する場合も、運用管理体制を確立しておくことが重要です。

この動向は、Webサービス提供者や開発者にとって、証明書管理戦略の再考を促すものです。
