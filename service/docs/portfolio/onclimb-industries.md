## 概要

Claude Code の Agent Skills を管理する公開リポジトリ。「今日の作業をまとめて」「請求書を作って」といった日本語の指示から該当スキルが起動し、作業記録・報告スライド・議事録・ナレッジベース・コードレビュー・設計ドキュメントなどの成果物を生成する。個人のエンジニアリング業務・フリーランス業務の広い範囲をカバーする。

## 背景・課題

日々の作業記録・依頼者向け報告・請求書などの定型業務と、コードレビュー・設計・調査などの技術作業を、毎回ゼロから AI に指示するのは非効率で品質もぶれる。手順・様式・品質基準をスキルとしてコード化し、再現可能な形で蓄積するために構築した。

## アーキテクチャ

スキルは分類プレフィックス（jarvis / friday / ultron / arc-reactor など）で体系化し、分類ごとの共通ルール（役割・言語表記・原則・品質基準）を persona ファイルに集約。スキルの生成データは git 管理外のデータディレクトリに置き、外部プロジェクトからは一方向に参照させる依存設計を敷いている。

### コンポーネント

#### Skills

分類プレフィックス付きの Agent Skills 群。記録系・ドキュメント系・お金系・エンジニアリング系などをカバー

- SKILL.md（Markdown 定義）
- Python スクリプト

#### Personas

分類ごとの共通ルール定義。スキル横断で文体・品質・安全性の基準を統一

- Markdown

#### Hooks

技術的なガードレール。学習用ディレクトリへの AI 書き込み拒否などを強制

- Claude Code Hooks
- Python

## 技術的な工夫

### persona によるスキル横断の品質統一

スキルごとにルールを書くのではなく、分類単位の persona ファイルに役割・原則・品質基準を集約。新スキル作成時は persona を参照する規約にすることで、40 超のスキルの文体・品質を少ないルール記述で統一した。

### 2 段構成のドキュメント生成パイプライン

自由形式ドキュメント（設計書・提案書・技術記事）は、目的と読者を確定させる企画ステージと、種類別の生成ステージに分離。「何をなぜ書くか」を先に固めることで、生成物の的外れを減らした。

### スキルとデータの一方向依存

スキルのデータは外部プロジェクトに保存せず、リポジトリ直下の git 管理外ディレクトリに置く。プロジェクト側が使いたい場合は設定（環境変数等）で取得元を指定させ、依存を常に一方向に保つことで、スキル単体で完結して動く状態を維持している。

### フィードバックの中央インボックス運用

スキル利用で出た不満・改善点は中央のインボックスに蓄積し、一定量たまってからまとめてレビュー・適用する運用。1 件の不満で定義を書き換えない規律により、スキル定義の安定性を保っている。

## 課題と解決策

### AI に任せない領域の技術的担保

**課題**: 学習目的のコードは AI に書かせず自分で書きたいが、運用ルールだけでは徹底しにくい

**解決策**: PreToolUse フックで特定ディレクトリへの書き込みツール実行を拒否し、「AI がコードを書けない領域」を技術的に強制した。

## 成果・学び

- 作業記録 → 報告 → 請求書という業務パイプラインをスキル連携で自動化
- Agent Skills の設計パターン（persona・2 段構成・データ分離・フィードバックループ）を確立
- AI エージェント運用における「任せる範囲」と「人が握る範囲」の切り分けの実践知を蓄積
