# デザインシステム仕様書（onclimb 山荘）

homepage の見た目と構成の正本。部品とページは、この仕様書の値と決まりに従って作る。
値を変えるときは、先にこの文書を書き直す。

モック（形・並び・寸法の見本）は `docs/design-system/mock/` にある。読み方は同じフォルダーの `README.md`。

## 1. 原則

- 方針は「シンプル・無骨・技術屋丸出し」。見た目で目を引くのではなく、仕組みが本物であることで見せる
- 装飾を使わない: ぼかしのある影・グラデーション・半透明・角丸・アイコン・スクロールに合わせた動き
- 罫線は 1px
- 読むのは主に「エンジニアに仕事を頼む側の人」。ターミナルの文法（プロンプト・コマンド・パス）は残しつつ、色・文字・行間は一般の読み物の水準にそろえる
- 名前の表記は `onclimb`（おんりむ）にそろえる。本名のローマ字は、画面の文言・プロンプト・コマンドの例に使わない（`guest@onclimb`、`man onclimb`、`finger onclimb`、`/home/onclimb`）

## 2. コンセプト「onclimb 山荘」

サイトを、onclimb の経歴・技術・作ったもの・考えを階ごとに置いた山荘として見せる。

### 階と URL

階は 5 つで固定する。部屋は、各階に置くデータに応じて増える。

| 階 | URL | 名前 | 分類 |
|---|---|---|---|
| 屋上 | `/rf` | 屋上テラス・外部リンク | なし（外のサイトへの扉を並べる） |
| 3F | `/3f` | 作ったもの・考え | `/3f/portfolios` `/3f/notes` `/3f/books` |
| 2F | `/2f` | 経歴・業務の技術 | `/2f/histories` `/2f/skills` |
| 1F | `/1f` | プロフィール・連絡先 | `/1f/profile` `/1f/contact` |
| B1 | `/b1` | 自己学習 | `/b1/studies` |

- 階の分け方: 変わらないこと（自己紹介・関心・資格）と連絡先は 1F、関心を持って独自に勉強したことは B1、実際に行ってきた事実は 2F、作ったものや考え方など思想に近いものは 3F、外のサイトへの出口は屋上
- 分類の slug は複数形にする。1 枚だけのページ（`profile` / `contact`）は単数にする
- 詳細は分類の下に置く（例: `/2f/skills/typescript`）
- 仮想パスは URL と同じ構成にする（`~/2f/skills/<category>/<name>.md`）。`ls ~` を打つと `b1 1f 2f 3f rf` が並ぶ
- 技術の階: 業務で使ったものは 2F、自己学習は B1。md の `context` 欄で決め、欄が無いものは level で決める（3 以上 = 業務、2 以下 = 自己学習）
- `/3f/notes` と `/3f/books` は、置くデータ（ノートの本文・本の md）ができてから作る。それまでは、分類の定義・扉・部屋に出さない

### ページの 4 種類

| 種類 | 例 | 上からの並び |
|---|---|---|
| 案内所 | `/` | タイトル「onclimb 山荘」→ `Contact` → フロアガイドと地図・その横に案内人の PC |
| 階 | `/2f` | 見出し（階の番号と名前だけ）→ 分類への入口の扉 → その階の地図・その横に案内人の PC |
| 分類 | `/2f/skills` | のぞき窓 → コマンド → 見出し → 一覧 |
| 詳細 | `/2f/skills/typescript` | のぞき窓 → コマンド → 見出し → 本文 → 前後へ移る扉 |

- どのページにも、見出しの下の説明文（リード）は置かない。見た目で分かるようにする
- 案内所は 1F とは別のページで、どの階の地図もここで見られる
  - 最初の画面は、タイトルと山荘の外観だけにする（ヘッダー・フッター・説明文を出さない）。山荘のまわりには木を生やし、奥に山の稜線を置く
  - 押すと入口へ寄り、扉が開いて中に入る。中は 1F を選んだ状態で始まる
  - 同じ訪問中に Home へ戻ったときは、中から始める
  - `Contact` は連絡先へのリンクで、見た目は扉の形のボタン（枠はアクセント色）。横に「お仕事のご相談、技術的なご相談・壁打ちを受け付けています」の一文を添える
- 階のページの扉は、表札に分類の名前と件数を出し、扉の下に URL を添える。屋上は外のサイトへの扉を並べる
- のぞき窓は、その階の小さな地図で「いまいる部屋」を選んだ状態にした帯。分類のページでは階へ戻る扉と同じ階のほかの分類への扉を、詳細のページでは一覧へ戻る扉と階へ戻る扉を添える。詳細のページでは、その紙がある部屋 1 つを選んで名前を出す（ブログのタグのように、どの分類・分野の内容かが一目で分かる）
- 分類と詳細のページの見出しには、その状態を作ったコマンドを添える

| ページ | コマンド |
|---|---|
| `/1f/profile` | `$ man onclimb` |
| `/1f/contact` | `$ finger onclimb` |
| `/2f/histories` | `$ ls -tr ~/2f/histories` |
| `/2f/skills` | `$ ls -l ~/2f/skills \| sort -k level` |
| `/b1/studies` | `$ ls -l ~/b1/studies \| sort -k level` |
| `/3f/portfolios` | `$ git log --oneline ~/3f/portfolios` |
| `/3f/notes` | `$ ls ~/3f/notes` |
| `/3f/books` | `$ ls ~/3f/books` |
| 詳細 | `$ cat ~/2f/skills/<category>/<name>.md` の形 |

### 外枠

- 現在地はシェルのプロンプト風に出す（`guest@onclimb:~/2f/skills$`。Home は `guest@onclimb:~$`）。`guest@onclimb` は prompt 色、パスは link 色
- ナビは「案内 / B1 自己学習 / 1F プロフィール / 2F 経歴・技術 / 3F 作品・考え / 屋上 リンク」。今いる階はアクセント色の下線で示す
- テーマは light / dark。既定は OS の設定に従い、選んだ後はその選択を優先する

### 案内人の PC

- 地図のあるページ（案内所と階のページ）で、地図の横に常に出す。狭い画面では地図のすぐ下に出す
- いま見ているものを文章で案内する（`$ docent` の出力として見せる）。続けて、置いてあるもの・行き先のボタン・部屋の一覧・探しもののコマンドのボタンを 1 つの枠にまとめる。階や部屋の概要は、別の枠にしない
- `Contact` は常に出す
- ボタンで動く版のあいだは、見出しの右に小さく「ボタン版」と出すだけにする。長い注記は書かない
- 後で、ブラウザ内で動く Linux と本物の `docent` に置き換える

### 案内人の文面と探しもの

案内人の PC に出す文面と、探しものの決まり（最初の版）。文面の元になる説明は定義（`FLOORS`・`SOCIAL_LINKS`）が持ち、案内の組み立ては純粋関数（`lib/building/guide.ts`）、探しものの計算は `lib/building/searches.ts` にある。案内所と階のページで同じものを使う。

**階の説明**（`FLOORS` の `description`）

- B1: 関心を持って、個人開発や勉強で身につけた技術の階です。
- 1F: 入口のある階です。自己紹介と、連絡先があります。
- 2F: 実際に仕事で行ってきたことと、そこで使ってきた技術の階です。
- 3F: 事実というより、考え方や思想に近いものを置いた階です。
- 屋上: 屋上です。ここから外のサイトへ出られます。

**部屋の説明**（分類の `roomDescription`、屋上は `SOCIAL_LINKS` の `description`）

- スキル・自己学習の分野の部屋: （分野の名前）の技術を、経験の深い順に置いてあります。
- プロフィール: 自己紹介と、変わらず持ち続けている関心、取得した資格です。
- 受付・連絡先: お仕事のご相談、技術的なご相談・壁打ちを受け付けています。帰る前に、ここで用件を伝えられます。
- 経歴: 組み込みから Web、機械学習、AI まで。関わってきた仕事を古い順に置いてあります。
- 作ったもの: 個人で設計・開発・運用しているプロダクトです。
- 屋上の部屋: GitHub = ソースコードを置いている GitHub へ出ます。 / Zenn = 技術記事を書いている Zenn へ出ます。 / X = X（@onc_limb）へ出ます。

**案内の文章**（`$ docent` の出力。変わったときは `aria-live` で伝える）

- 階を選んでいて、部屋を選んでいないとき: 「ここは （階の番号）「（階の名前）」です。（階の説明）部屋を押すと、中身をお見せします。」
- 部屋を選んでいるとき: 「「（部屋の名前）」です。（部屋の説明）」。置いてあるものがあるときは、続けて「置いてあるものは、下のとおりです。」
- 階段を選んでいるとき: 「階段です。上の階・下の階へは、下の一覧から移れます。」
- 屋上の部屋を選んでいるとき: 「（部屋の説明）外のサイトが別のタブで開きます。」
- 探しものの後で、部屋を選んでいないとき: 「（件数） 件見つかりました。光っている部屋を押すと、中身をお見せします。ほかの階にもあるときは、階の横に件数が出ています。」（件数を出さない探しもの `tree` では、階の案内のまま）
  - 階のページ（フロアガイドが無い）では: 「（件数） 件見つかりました。この階には（n） 件あります。光っている部屋を押すと、中身をお見せします。ほかの階の紙は、下のパスから移れます。」。この階に無いときは「この階にはありません。」、全部がこの階にあるときは最後の文を出さない

**置いてあるもの**

- 階のとき: その階の分類の一覧（名前と、件数か一言）
- 部屋のとき: その部屋の紙の先頭 5 件（題名と一行）と「ほか n 枚」。スキルは経験の深い順（level の降順、同じ level は名前順）
- 紙の無い部屋（連絡先）・階段・屋上の部屋・屋上の階では出さず、行き先のボタンだけを出す

**行き先のボタン**（最後は必ず `Contact`）

- 階のとき: 「（階の番号） のページへ」（案内所だけ。階のページでは出さない）
- 部屋のとき: 「（分類の名前）のページで読む」
- 屋上の部屋のとき: 「（名前） を開く」（↗ は `DoorButton` が付けるので、文言には書かない）

**部屋の一覧**

- 階のとき: 見出し「この階の部屋」で、その階の全部の部屋と階段
- 部屋のとき: 見出し「つながっている部屋」で、「廊下へ戻る」と、同じ階のほかの部屋と階段
- 階段のとき: 「廊下へ戻る」と、上の階・下の階（屋上は下の階だけ、B1 は上の階だけ）。見出しは部屋のときと同じ「つながっている部屋」。案内所では階を切り替え、階のページではその階のページへのリンクにする
- 一覧から選ぶと、地図でも同じ部屋が選ばれる

**探しもの**

| 説明 | コマンド | 結果の一言 |
|---|---|---|
| AI に関わるもの | `grep -rl ai ~` | AI に関わる紙が見つかりました |
| 設計に関わるもの | `grep -rl architecture ~` | 設計に関わる紙が見つかりました |
| いちばん得意な技術 | `grep -rl 'level: 5' ~` | レベル 5（専門）の技術です |
| 建物の構成を見る | `tree -d -L 2 ~` | 階と分類の一覧です |

- `grep -rl <語> ~`: 紙の題名・一行・タグ・分野のどれかに、その語が「英字の単語として」あるもの。大文字と小文字は区別しない。前後が英字でない位置にあるときだけ当たる（`ai-llm` や「AIドキュメント検索」は当たり、`Tailwind` や `container` は当たらない）。パスと URL は見ない。1 枚は 1 回だけ数える
- `grep -rl 'level: 5' ~`: level が 5 のスキル
- 上の 3 つの結果は「（件数） 件。（結果の一言）」と、当たった紙の仮想パスの一覧。当たった紙のある部屋が地図で光り、フロアガイドの階の横に階ごとの件数（紙の数）が出る。パスを押すと、その階と部屋が選ばれる（階のページで別の階のパスなら、その階のページへ移る）
- `tree -d -L 2 ~`: 件数は出さず、部屋も光らせない。屋上から B1 の順に、階ごとに 1 行（例: `~/2f/histories  ~/2f/skills`、屋上は `~/rf`）。行を押すと、その階が選ばれる（階のページで別の階の行なら、その階のページへ移る）
- 絞り込みは Server Component で先に計算し、props で渡す（紙の数は 100 余りなので、4 つのコマンドの結果を全部渡す）

### ボタン

- ボタンは扉の形にそろえる（板張りの地・木の色の太い枠とその外側の細い線・右端に小さな四角い取っ手）
- 主な行き先（`Contact`・送信）と、押されている状態は、枠をアクセント色にする
- 扉の形にするのは「ボタン」だけ。文中のリンク・ナビの項目・検索結果のパスは下線付きの文字のまま、地図の部屋とフロアガイドの階は地図の描き方のままにする

### 動き

スクロールに合わせた動きと装飾の動きは使わない。認めるのは次の 3 つだけ。`prefers-reduced-motion` では動かさない。

1. 最初の画面から中に入る動き（入口へ寄る・扉が開く）
2. 階を移るときに地図が上下に動く
3. 部屋の色が変わる

## 3. トークン

### 色

文字に使う色（fg / fg-muted / accent / prompt / link）は、bg・surface・木の床に対してコントラスト比 4.5:1 以上にする。

配色のねらい: 山の中に建つ木造の山荘。地は緑、建物・床・扉は木の色。light は昼の山荘（黄緑の地）、dark は夕方の山荘（深い緑の地。アクセントは窓の明かりの色）。
この配色は最初の版とする。今後、少しずつ写実的な方向へ改良していく（そのつど値をここに書き直す）。

## 4. 地図

- 上から見下ろす 2D の絵にする（45° 回して縦を 1/2 にした投影。CSS では `scaleY(0.5) rotate(45deg)`）。3D のライブラリは使わない
- 建物は幅 760 × 奥行 520 の長方形。どの階も同じ骨組みにする: 中央に廊下（奥行 60）が 1 本通り、部屋はその両側に 1 列ずつ並ぶ。階段は全階で同じ位置
- 部屋の位置と大きさは、手で決めずにデータから計算する。部屋の幅は「紙の枚数 + 3」の比で配分する。部屋が増えると、同じ階の部屋が詰まる
- 部屋の幅の最小は 48。下回る部屋は 48 にして、残りの幅を残りの部屋に同じ比で配り直す。それでも収まらない数のときは、エラーにせず均等に割る
- 部屋 = その階の中のまとまり。スキルは分野ごとに 1 部屋、ほかは分類 1 つが 1 部屋
- 入口は 1F の廊下の端、出口は連絡先の部屋の外壁に置く。1F の手前にはデッキを付ける
- 部屋の状態: 通常 / 選んでいる（prompt 色の太い枠）/ 光る（accent 色の枠と `--ds-map-lit` の地。検索で該当したとき）
- 部屋のラベルは名前だけにする（枚数などの数字は地図に出さない）。ラベルは変形の外に置き、文字を傾けない
- 検索で光った部屋には印（●）を付け、件数はフロアガイドの階の横に出す。地図の凡例は置かない
- 素材で山荘らしさを出す。床は板の目地を縦線で入れ、奥側の 2 面に壁を立てる。1F〜3F は木、B1 は石、屋上とデッキは板張りのテラス（壁は立てず、低い縁だけ）
- 目地は CSS のグラデーションを使わずに描く（SVG の pattern など）。壁と床板の厚みは、ぼかしの無い単色のずらし（`box-shadow` のぼかし 0）か、別の要素で描く
- フロアガイドは、屋上から B1 までを縦に並べ、上に屋根の形を置いて山荘の断面に見せる。B1 は石の色にする
- 狭い画面では地図を小さく出し（ラベルなし）、部屋は案内人の PC の「この階の部屋」の一覧から選ぶ
- 次の段階で、同じ建物のデータを一人称の 3D で歩けるようにする。2D の地図は、そのときも案内所と階のページに残す

## 5. 部品

`service/components/ds/` に置く。部品とトークンの見本は `/design`（検索に載せないページ）で確かめる。

| 部品 | 役割 |
|---|---|
| `Page` | ページの枠。見出し（`h1`）、任意のコマンド（見出しの上）、任意ののぞき窓（その上） |
| `Section` | man page 風の大文字見出し（`h2`）で区切るセクション |
| `KeyValue` | キーと値の一覧（`dl`） |
| `DataTable` | 表。罫線 1px、狭い画面では表の中だけ横にスクロール |
| `TextLink` | リンク。外部は `↗` を付けて新しいタブで開く |
| `LogList` | `git log --oneline` 風の一覧（日付・識別子・題名・一行の説明） |
| `CodeBlock` | コマンドやコードの表示（`pre`） |
| `Prose` | Markdown の本文。`##`〜`####` の見出しには、`HashHeading` と同じ `#`・`##`・`###` の印を付ける |
| `HashHeading` | 薄い `#` の印を付けた見出し（`h2` は `#`、`h3` は `##`、`h4` は `###`）。印は読み上げない |
| `DoorButton` | 扉の形のボタン。小（ふつうのボタン）と大（分類への入口） |
| `PagerDoors` | 詳細のページの末尾に置く、前・一覧へ戻る・次の扉 |
| `FloorMap` | 階の地図 |
| `FloorGuide` | フロアガイド（山荘の断面） |
| `GuidePc` | 案内人の PC |
| `LodgeExterior` | 山荘の外観（最初の画面） |
| `PeekBand` | のぞき窓 |

使い方の例（分類のページ）:

```tsx
<Page title="スキル" command="ls -l ~/2f/skills | sort -k level" peek={<PeekBand floor="2f" group="skills" />}>
  <DataTable columns={columns} rows={rows} />
</Page>
```

## 6. 広告

AdSense は続ける。広告は分類と詳細のページの末尾にだけ置き、案内所（Home）・階のページ・連絡先には置かない。
広告の上には 1px の罫線と、`fg-muted` の小さな「広告」の表記を置き、幅は本文と同じ幅に収める。広告の枠に装飾は足さない。

## 7. 旧デザインの資料との関係

`docs/design/`（2026-04 の素案）と `docs/style/opaque-surfaces.md` は、以前のデザインの資料。歴史の資料として残すが、新しい実装はこの仕様書に従う。
旧デザインのトークンとクラスは、全ページの移行が終わるまで新しいトークン（`--ds-*`）と並存させ、最後にまとめて消す。
