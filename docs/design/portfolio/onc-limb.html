/01

作成背景

— why I built this

SNSやQiitaに分散していた発信を、自分自身のドメインに集約したかった。プロフィール・技術スタック・読書記録・情報収集ログを一元化することで、エンジニアおよび非エンジニアに向けて「自分が何者か」を一目で伝えられる場を作る。

同時に、自分が興味を持つ エッジコンピューティング・低レイヤー寄りのアーキテクチャ を実際に運用する場として実験台にしたかった。仕事で使う技術スタックとは別軸で、Cloudflare Workers / D1 / OpenNext などをプロダクション運用することで、技術判断の引き出しを増やすのが裏目的。

「動く理由を知り、使う人を想う」を体現する場として、自分自身が最もハードなユーザーになる。

更新が止まれば自分の手抜きが可視化される。サボれない仕組みとして、本気で使い倒すホームページを目指した。

/04

工夫した点

— what I obsessed over
01

エッジでのフルスタック完結

OpenNext を介して Next.js App Router 全体を Workers にデプロイ。レンダリング/API/DB アクセスをすべてエッジで完結させ、コールドスタートを最小化。

avg TTFB: ~80ms (Tokyo)
cold start: < 50ms
cf-cache-status: HIT 比率 >70%
02

D1 + Drizzle で型安全なスキーマ駆動

Cloudflare D1 (SQLite) を Drizzle ORM 経由で操作。スキーマを単一ソースとし、マイグレーションも型もコードで管理。Drizzle Studio で Markdown ノートも CRUD できる。

schema.ts → migrate → typed queries
zod でランタイム検証も二重化
03

News の AI 要約パイプライン

Cron Triggers が定期的に RSS / HN / GitHub Trending を取得。LLM で3 行要約 + タグ付けを生成し、D1 にキャッシュ。トップは静的に近い速度で配信される。

cron: 0 */3 * * *
cost: $0.04 / day
token usage の自動アラート付き
04

Markdown コンテンツのハイブリッド管理

プロフィールや読書メモはリポジトリ内の Markdownとして管理し、gray-matter でメタデータを抽出。下書き状態のコンテンツだけ D1 に保存して切替可能。

/content/**/*.md ← git-managed
D1.drafts ← admin で編集
05

Preview Deploy でゼロリスク改修

PR ごとに Wrangler が一意ドメインを発行。本番と同等の D1 ブランチに接続することで、データの絡む UI 変更も安心して試せる。

PR #N → onclimb-pr-N.dev
D1 branch → cleanup on merge
06

読みやすさを最優先したタイポ設計

エンジニアにも非エンジニアにも読みやすいよう、本文は Inter + Noto Sans JP の混植。font-feature-settings, text-wrap: pretty を要所で使い分け。

body: 16px / line-height 1.85
letter-spacing: 0.005em (JP)
code: JetBrains Mono
