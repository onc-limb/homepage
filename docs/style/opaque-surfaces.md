# UI スタイル方針: 半透明禁止・不透明背景 + border + 影

本サイト（`service/` 配下）の UI コンポーネントに適用するサーフェス（背景面）のスタイル方針を定める。半透明スタイルの再導入（負債の自己増殖）を防ぐことを目的とする。

## 方針

UI コンポーネントは半透明背景（`backdrop-blur` / 透過色 `bg-<color>/<opacity>` / `rgba()` の透過背景）を使わず、不透明の単色背景 + border + 控えめな影とする。背景色 × 通常テキスト色は WCAG 2.2 AA（4.5:1）を満たすテーマトークンを参照し、コンポーネントへの色の直書きはしない。ヘッダー（`service/components/header/` 配下）の `backdrop-blur` のみ例外として許容する。

## 背景

半透明サーフェス（ガラスモーフィズム風）には次の 2 つの問題がある。

1. 半透明のオブジェクトが「AI 生成サイトっぽい」印象を与え、ポートフォリオ兼技術発信の場としての自己提示を損なう。
2. 背景が透けることでテキストのコントラストが背後のコンテンツ次第で変動し、可読性が下がる。WCAG 2.2 AA（達成基準 1.4.3: 通常テキスト 4.5:1）を安定して満たせない構造的な弱点となる。

不透明の単色背景 + 明確な境界線（border）+ 控えめな影という構成に統一することで、テキストコントラストを背景コンテンツに依存させず WCAG 2.2 AA（4.5:1）を明示的に満たし、テンプレート/AI 生成的な印象を排除する。

## トークンの一元管理

置き換え後の **背景色・境界線色・影** は、**ライト/ダーク両テーマ分**をテーマ機構（`service/lib/theme` 周辺のカラートークン）またはグローバル定義（グローバル CSS 変数 / Tailwind 設定）で **1 箇所に一元管理**する。各テーマの値はここでのみ定義し、コンポーネント側は必ずそのトークンを参照する。

- コンポーネントファイルへの新規カラーコード直書きはしない（背景色・境界線色・影のいずれも）。
- 背景色とその上に載る通常テキスト色の組み合わせは、ライト/ダーク両テーマで WCAG 2.2 AA のコントラスト比 4.5:1 以上を満たす値を選定する。
- **新規コンポーネントも例外なく**、同じトークンを参照して不透明背景 + border + 控えめな影を構成する。独自の半透明背景や色の直書きを新たに持ち込まない。

## ヘッダーの例外

ヘッダー（`service/components/header/` 配下）の `backdrop-blur` は、スクロール時にコンテンツと重なる部分の常套手段であるため、**例外として現状維持する**（撤廃しない）。この例外はヘッダー配下に限る。

## grep での確認基準（棚卸し）

`service/` 配下（`.tsx` および `.css`）を次のパターンで grep し、半透明スタイルが残っていないことを確認する。

- `backdrop-blur` … ヒットは `service/components/header/` 配下のみであること。
- `bg-white/` ・ `bg-black/` 等の Tailwind 透過修飾子（`bg-<color>/<opacity>`） … ヘッダーを除き 1 件も残っていないこと。
- `rgba(` の透過背景 … ヘッダーを除き 1 件も残っていないこと。CSS Modules / グローバル CSS も対象に含める。

装飾以外の用途で意図的に半透明を残す場合は、コード内に `// ASSUMPTION:` コメントで理由を明記する。
