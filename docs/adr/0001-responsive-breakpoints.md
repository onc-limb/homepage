# ADR-0001: 画面の幅による切り替えは、アプリで共通の名前付きの境目と CSS だけで行う

- ステータス: 採用
- 日付: 2026-11-26

## 結論

画面の幅で見た目を切り替える境目は、アプリ全体で共通の名前付きの組（Tailwind の `md` 768px・`lg` 1024px・`xl` 1280px）だけにする。部品やページが自分の境目の値を持つことはしない。
切り替えは CSS のメディアクエリだけで行い、JavaScript で幅を読まない。1 つの部品の中で切り替えられるものは中で切り替え、同じ絵を 2 組描いて片方を隠す形は、構造そのものが違うときに限る。

## 背景

- リニューアルの job が進むにつれ、幅による切り替えが部品ごとにばらばらになった（レビューの A-6。`docs/ideas/renewal-review-2026-11-25/README.md`）。
  - ページの余白・フロアガイドの向き（job 16）・案内所の並び（job 19）は Tailwind の `md:`（768px）で切り替えている。
  - ヘッダーのナビとテーマの文言は、`components/ds/screen-styles.ts` で `[@media(min-width:880px)]` を直に書いている。
  - FloorMap は `size="normal" | "small"`、LodgeExterior は `size="desktop" | "narrow"` の prop で大きさを変える。どの幅でどちらを使うかは、置く側が決めている。
  - 仕様書（`docs/design-system.md`）は「狭い画面では〜」と書くが、狭い画面がどの幅かを決めていない。
- job 19（PR #379）では、この ADR が無いまま「既存の方式に合わせ、新しい境目を作らない」とだけ指示して走らせた。その結果、次の問題が後の job へ持ち越された（`docs/ideas/renewal-review-2026-11-26/pr-379.md` の 2・3・5 番）。
  - 並びと地図の大きさを同じ `md` で切り替えたので、job 20 の「案内人の PC を地図の横に置く」の幅が残らない（1240px の画面でも約 142px）。
  - job 21 の外観は幅 1000px の固定なので、`md` で出し分けると 768〜1000px ではみ出す。
  - 地図を normal と small の 2 組描いて片方を隠したので、Home が約 3,000 要素・約 300KB になった。
- 方針として、境目はアプリ内で共通にしたい（本人の考え）。アプリによって境目の値や数は違ってよいが、1 つのアプリの中では、部品ごとに別の値を持たせない。

## 前提

- 見た目の正本は仕様書とモック（`docs/design-system/mock/`）。モックの広い画面は、ページの枠の上限 1240px（中身 1160px）で、[地図 762px | 間 24px | 案内人の PC 約 374px] の 2 列になっている。
- ページは SSR（OpenNext on Cloudflare Workers）で描き、JavaScript が無くても正しい方が出ることを求める（job 19・21 の指示書）。
- 旧デザインの CSS は job 25 で消すまで残る。旧デザインの部分は Tailwind の既定の `sm`・`2xl` なども使っているので、`theme.screens` を削るのは job 25 の後にする。
- 境目の値を変えるのは、モックの寸法やナビの項目数が変わったとき。そのときはこの ADR の表を直す。

## 検討した案

### A. 部品ごとに、必要な幅で切り替える（今の状態）

- 良い点: 部品ごとに、ちょうどよい幅を選べる。
- 弱い点: 境目が部品の数だけ増える。同じ画面に並ぶ部品が別の幅で切り替わり、768〜1280px の間で中途半端な組み合わせが出る。どの幅を確かめればよいかが、部品を読まないと分からない。

### B. 境目は `md` の 1 つだけにする（job 19 の選び方）

- 良い点: いちばん単純。境目を増やさない。
- 弱い点: 「狭い ↔ 広い」と「2 列が入る幅」は別の問題なのに、1 つの値で兼ねることになる。PC を地図の横に置く幅や、ヘッダーのナビが 1 行に入る幅を表せない。

### C. アプリで共通の、名前付きの境目の組から選ぶ（採用）

- 内容: 境目は `tailwind.config.ts` の `theme.screens` の名前（`md`・`lg`・`xl`）だけにする。値は Tailwind の既定のまま使い、新しい名前は足さない。部品は、表の「役割」に当たる名前を選ぶ。任意の値のメディアクエリ（`[@media(min-width:…)]`・`min-[…]:`・`max-[…]:`）は書かない。
- 良い点: 確かめる幅が決まる（390・768・1024・1280）。同じ画面の部品が同じ幅で切り替わる。値が 1 か所にある。
- 弱い点: 部品にとってちょうどよい幅とずれることがある。そのぶんは、部品の側を割合で描くなどして、境目に合わせる。

### D. JavaScript で幅を読んで切り替える（`matchMedia`・`ResizeObserver`）

- 良い点: 1 組だけ描けばよく、DOM が増えない。
- 弱い点: SSR の HTML と最初の表示が食い違い、ちらつく。JavaScript が無いと決まらない。境目の値が JavaScript にも要り、出どころが 2 つになる。

## 採用の理由

- 本人の方針（境目はアプリ内で共通）に沿うのは C だけ。
- B では job 20・21 の要求が入らないことが、job 19 のレビューで具体の数字として分かった。
- D は、SSR と「JavaScript が無くても正しい方が出る」という前提に反する。
- 値を Tailwind の既定に合わせれば、新しい名前を覚える必要が無く、`md:`・`lg:`・`xl:` の接頭辞がそのまま役割の印になる。

## 境目と役割

| 名前 | 値 | 役割（この幅以上で切り替わるもの） |
|---|---|---|
| （無し） | 〜767px | 狭い画面。1 列に縦に並べる。確かめる幅は 390px |
| `md` | 768px | ページの左右の余白を広げる。フロアガイドを縦一列にする。地図を大きい方（ラベル付き）にする。外観を広い方にする |
| `lg` | 1024px | ヘッダーのナビとテーマの文言を 1 行に出す（今の 880px をここへ寄せる） |
| `xl` | 1280px | 地図のあるページで、[地図 | 案内人の PC] の 2 列にする。これより狭いときは、仕様書の「狭い画面」と同じく PC を地図のすぐ下に出す |

- `xl` を 2 列の境目にするのは、モックの寸法（地図 762px + 間 24px + PC 約 374px = 1160px）がそのまま入る最初の既定の境目だから。`lg`（中身 944px）では、地図を約 550px に縮めることになり、2F の部屋のラベルが重なる。
- 表に無い役割が出てきたら、まず表の名前のどれかに当てはめる。当てはまらないときは、この ADR を直してから使う（部品の中で値を足さない）。

## 切り替え方の決まり

- CSS のメディアクエリ（Tailwind の接頭辞）だけで切り替える。JavaScript で幅を読まない。
- 1 つの部品の中で切り替えられるもの（ラベルを出す・出さない、余白、向き、大きさ）は、部品の中で `md:` などを使って切り替え、DOM は 1 組にする。
- 同じ絵を 2 組描いて片方を `hidden` にする形は、狭い方と広い方で構造そのものが違い、中で切り替えられないときだけにする。そのときも、2 組にするのは違う部分だけにする。
- 大きさが固定の絵（地図・外観）は、枠の寸法を名前付きの値（`tailwind.config.ts` の `maxWidth`）で持ち、中は割合と `aspect-ratio` で描く。こうすると、境目の間の幅でも絵が縮むだけで、はみ出さない（レビューの A-7）。
- 変種の名前: 幅で出し分ける変種は `narrow | wide`、大きさだけが違う変種は `small | large` にする。今ある `normal | small`（FloorMap）・`desktop | narrow`（LodgeExterior）は、次に手を入れる job で直す。

## 影響範囲

- **job 20（案内人の配線）**: 指示書の「守ること」にこの ADR を足す。案内所と階のページは、`xl` 以上で [地図 | PC]、未満で地図の下に PC。広い画面のフロアガイドは、モックどおり地図の左上に重ねる（job 19 の横並びを改める）。FloorMap は 1 組だけ描き、ラベルと大きさは部品の中で `md:` で切り替える（job 19 の 2 組描きを改める）。
- **job 21（最初の画面）**: 外観は `md` で narrow / wide を切り替える。その前に、外観を割合と `aspect-ratio` で描き直す（レビュー #376-1 の案 C）。描き直しは job 21 の前の小さな job か、job 21 の指示書で認める。
- **ヘッダー**: `components/ds/screen-styles.ts` の 880px を `lg` に寄せる。880〜1023px では、ナビがモバイルの形になる。
- **検査**: ds の部品とリニューアルのページに、任意の値のメディアクエリ（`[@media(`・`min-[`・`max-[`）が無いことを、横断のテストで確かめる。ヘッダーを `lg` に寄せたときに足す。
- **確かめる幅**: 人が画面で確かめる幅は 390・768・1024・1280px にする（各 job の指示書の「人が画面で確かめること」）。
- **仕様書**: `docs/design-system.md` の「狭い画面」を、この ADR の表で読むと書き足す。
